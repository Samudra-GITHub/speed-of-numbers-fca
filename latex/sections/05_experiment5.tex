\section{Experiment 5: Invent Your Own Fractions (Fixed-Point Q16.16 Arithmetic)}

\subsection{Aim}
To design and implement a fixed-point numerical representation (Q16.16) using only 32-bit signed integers, benchmark its execution latency for addition, multiplication, and division against IEEE single-precision floating point, and evaluate its mathematical accuracy against 64-bit double-precision reference values.

\subsection{Background}
Before the widespread adoption of on-chip hardware FPUs, embedded systems utilized \textbf{fixed-point arithmetic} to manipulate fractional numbers using integer ALUs. In the \textbf{Q16.16} format:
\begin{itemize}[noitemsep]
    \item A 32-bit signed integer (\texttt{int32\_t}) is partitioned into 1 sign bit, 15 integer magnitude bits, and 16 fractional bits.
    \item The scaling factor is $2^{16} = 65,536$. A real value $R$ is converted by computing $\text{round}(R \times 65536)$.
    \item \textbf{Smallest Resolution (1 LSB):} $2^{-16} = \frac{1}{65536} \approx 0.000015258789$.
    \item \textbf{Dynamic Range:} $[-2^{15}, +2^{15} - 2^{-16}] = [-32,768.0, +32,767.9999847]$.
\end{itemize}
Addition and subtraction operate natively on integer registers ($A + B$). However, fixed-point multiplication scales the result by $2^{32}$, requiring a right-shift by 16. Furthermore, multiplying two 32-bit integers can generate a 64-bit product; an intermediate 64-bit container (\texttt{int64\_t}) is required to prevent catastrophic arithmetic overflow:
\begin{equation}
    \text{Mul}_{Q16}(A, B) = \left( \frac{(A \times B)}{2^{16}} \right) \implies \texttt{(int32\_t)(((int64\_t)A * B) >> 16)}
\end{equation}
Similarly, fixed-point division requires pre-shifting the numerator:
\begin{equation}
    \text{Div}_{Q16}(A, B) = \left( \frac{A \times 2^{16}}{B} \right) \implies \texttt{(int32\_t)((((int64\_t)A) << 16) / B)}
\end{equation}
