## Executive Summary & Design Review Verdict

This document represents the **final design audit, architectural cleanup, and execution handoff** for the FCA "Speed of Numbers" project. 

The primary objective is to transition from initial scaffolding to an **industrial-grade, reproducible, zero-fabrication embedded systems research paper** maintained strictly in \LaTeX{}. 

### Architectural Review Findings & Policy Mandates:
1. **Total Elimination of Synthetic & Fabricated Measurements:**  
   All hardcoded cycle counts, timing durations, latency tables, speedup ratios, and empirical conclusions previously placed in documentation or placeholder text are **formally rescinded and expunged**. All numerical observations must dynamically enter the document through verified CSV tables and raw terminal logs generated by the physical ESP32 board.
2. **Strict Adherence to Predict $\to$ Measure $\to$ Explain:**  
   Every experimental module is structurally bifurcated. Predictions are captured in dedicated, immutable hypothesis containers before measurements occur. Analysis containers remain empty until real hardware data is ingested.
3. **Preservation of Firmware Artifact:**  
   The Arduino benchmarking sketch (`code/speed_of_numbers/speed_of_numbers.ino`) is treated as an immutable external implementation artifact. It is never modified or rewritten during document generation; it is referenced programmatically via line-numbered listings.
4. **Implementation Engine Delegation:**  
   Claude Code is designated as the sole implementation engine. This document provides the complete, unambiguous technical specification, file-by-file blueprint, component signatures, CSV schemas, build pipelines, and five sequential implementation milestones.

# PART 2 — Elimination of Fabricated Data & Zero-Tolerance Policy

### 2.1 The Problem
In early iterations, plausible or simulated cycle numbers (e.g., "114 cycles for 100 adds", "184.06 cycles for 64-bit divide", "39.5 microseconds for ADC") were drafted to test table layouts. While technically grounded in Xtensa architecture, embedding these numbers into source files violates the core philosophical requirement of the course:

> *"The cycle: Predict $\to$ Measure $\to$ Explain... Nobody will hand you the answers. Your team will design small experiments on the ESP32, measure what really happens, and explain it."*

### 2.2 Purge Protocol
1. **Source Text:** All concrete numbers in discussion sections are purged. In their place are explicit structural prompts and analytical questions for the student team to address once measurements are captured.
2. **Data Pipeline:** All CSV files in `/data/` are stripped down to **valid headers only** or headers accompanied by blank/placeholder rows (`NaN` or `-1` markers) required for LaTeX compiler stability.
3. **Visual Placeholders:** When data is pending, graphs must render an explicit, elegant visual banner indicating: `[Awaiting Hardware Measurement Data from Serial Monitor]`.

- **Table of Contents:** Formatted via `tocloft`. Section entries feature dotted leaders and bold page numbering.

Container for hypotheses formulated *strictly prior to measurement*.

Documents experimental repeatability, unroll count, loop baseline equations, and memory clobbers.

Surrounds the dynamically imported `pgfplotstable` and summary statistics.
- Left border: $2\,\text{pt}$ solid `BorderGray`

- Left border: $4\,\text{pt}$ solid `SlateText`

# PART 11 — Cross-Platform Build System

To guarantee flawless compilation across local developer machines, headless CI servers, and Overleaf, three build targets are established.

### 11.1 Target A: PowerShell (Windows / VS Code Native)
- **`scripts/build.ps1`**: Executes `pdflatex -> biber -> pdflatex -> pdflatex` with error catching.
- **`scripts/clean.ps1`**: Deletes `.aux`, `.log`, `.out`, `.toc`, `.bbl`, `.bcf`, `.run.xml`.
- **`scripts/watch.ps1`**: Continuously monitors `/latex/`, `/data/`, and `/figures/` and triggers re-compilation on file modification.

### 11.2 Target B: POSIX Makefile (Linux / macOS / GitHub Actions)
```makefile
TARGET = main
LATEX_DIR = latex
BUILD_DIR = build

all: $(TARGET).pdf

$(TARGET).pdf: $(LATEX_DIR)/$(TARGET).tex
	cd $(LATEX_DIR) && pdflatex -interaction=nonstopmode $(TARGET).tex
	cd $(LATEX_DIR) && biber $(TARGET)
	cd $(LATEX_DIR) && pdflatex -interaction=nonstopmode $(TARGET).tex
	cd $(LATEX_DIR) && pdflatex -interaction=nonstopmode $(TARGET).tex

clean:
	cd $(LATEX_DIR) && rm -f *.aux *.log *.out *.toc *.bbl *.blg *.bcf *.run.xml *.fls *.fdb_latexmk

watch:
	latexmk -pvc -pdf $(LATEX_DIR)/$(TARGET).tex
```

### 11.3 Target C: Overleaf Zero-Configuration Mode
All relative paths inside `latex/` use forward slashes (`/`). Compressing the `latex/` folder alongside `/data/`, `/code/`, and `/serial_logs/` produces an instant Overleaf project requiring zero configuration.
